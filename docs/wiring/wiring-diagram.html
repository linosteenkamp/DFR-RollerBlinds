What's still missing

  • OrderedSchottky diode on the XIAO’s 5 V feed (1N5822)

    Found on the bench: the XIAO’s 5V pin is also USB power, and without a diode that runs backwards through the buck onto the driver. Until it’s fitted, flash with USB only and the motor unplugged, and run on 24 V only. After fitting, check: 24 V only gives about 4.6 V on the XIAO 5V pin, and USB only gives about 0 V on VM.

  • Covered150 Ω series resistors: the MF0204FTE52-150R does this job

    The same part serves as the three keypad series resistors and the LED resistor. The design asked for 220–470 Ω, and 150 Ω works just as well: a pressed key reads 0.11 V, and the pull-up still sets the filter's corner. The only thing to check is quantity. Each unit takes four, so make sure you bought enough for every unit you're building.

  • If longTwisted or shielded 4-core cable for the keypad harness

    The filter handles noise at the pin. Cable choice and routing cut how much noise gets coupled in the first place. For a run longer than a hand-width that has to pass near the motor cable, twist each key line with the common, or use shielded cable with the shield grounded at the board end only. On a short run kept apart from the motor cable, no new cable is needed.

  • Nothing to buyMoving Fn off D6

    Done in the v2.4.0 pin map shown above: Fn on D3, LED on D2, D6 empty. It needs only the two wires moved and firmware v2.4.0. See "Rewiring a board" below.

  • Nothing to buyEverything else

    You don't need TVS diodes, ferrites or different values. Perfboard, heat-shrink and a little wire are all it takes to mount the parts.

Leave the internal pull-up enabled

HARDWARE.md used to say to switch keypad_init to GPIO_PULLUP_DISABLE once external pull-ups were fitted. Don't. Every unit runs the same OTA image, so that change would reach units that haven't been modified yet, and their key lines would float. That's exactly the input that fakes presses. In parallel with 4.7 kΩ the internal pull-up only moves the pressed voltage from 0.11 to 0.15 V at worst, so leaving it on costs nothing.

Rewiring a board

Firmware and wiring must match. The OTA image can't tell which wiring a board has.

Board wired forFirmwareResult
Old map (Fn D6, LED D3)v2.4.0 or laterUnsafe Fn reads the LED line, which sits near 1.5 V, between a valid low and a valid high. Fn can read as held, and 3 s of that enters Calibration Mode. The LED is dark and the real Fn key does nothing.
New map (Fn D3, LED D2)v2.3.x or olderWrong Old firmware drives D3 high as the LED, so pressing Fn pulls about 20 mA through 150 Ω. That's survivable, but Fn does nothing and the LED is dark.
  1. Power down: 24 V off, USB unplugged.
  2. Move the LED wire, with its 150 Ω, from D3 to D2.
  3. Move the Fn wire from D6 to D3, and fit its RC filter at the D3 end.
  4. Leave D6 empty.
  5. Flash or OTA v2.4.0 or later before relying on the keypad.
  6. Check that the LED shows its normal pattern. Then hold Fn for about 3 s from standstill: Calibration Mode's slow pulse should appear. Hold Fn again to exit.

After fitting

  1. Before powering up, check the electrolytic's polarity. The stripe marks the negative lead, which goes to GND.
  2. With the unit powered and idle, meter each of D3, D4 and D5 to GND. Expect about 3.3 V.
  3. Hold each key and read it again. Expect about 0.1 V. If it stays near 3.3 V, the key isn't reaching the node: check the harness and the series resistor's joints.
  4. Hold Up. EN̅ (D9) should read 0 V for the whole hold, which proves the path end to end.
  5. Leave the unit untouched for a day. Note the start time so that any travel logged afterwards is provably unattended.
